Leaf Vein Workflow の挙動と関数の流れ

このノートの目的

このノートは、leaf-vein-workflow の現在の MVP 実装について、人間が読んで流れを理解するための説明です。

このプラグインが今やることは、次の 2 点に絞られています。

  • napari で画像を開き、長方形 ROI を 1 つ描き、Add ROI ボタンを押したときだけ、その範囲の切り抜き画像レイヤーを作る。
  • 切り抜き画像から、手動閾値または Otsu 閾値で葉脈候補の mask Labels レイヤーを作る。
  • mask Labels レイヤーから骨格化 Labels レイヤーと、手動分類用の order labels レイヤーを作る。

まだ扱わないことは、複数 ROI、ポリゴン ROI、画像の保存、nD stack、骨格のセグメンテーション、VLA の計算、major/minor の自動分離です。

ユーザーから見た流れ

ユーザー操作としては、次の順番になります。

  1. napari を起動する。
  2. Plugins > Leaf Vein Workflow > Leaf Vein Workflow から widget を開く。
  3. napari 標準の方法で葉画像を開く。
  4. プラグインが自動で ROI 用の Shapes レイヤーを作る。
  5. 画像上に長方形を 1 つ描く。
  6. Add ROI ボタンを押す。
  7. 長方形の範囲だけを切り抜いた Image レイヤーが追加される。
  8. crop 画像から二値 mask の Labels レイヤーが自動で追加または更新される。
  9. 必要なら Use Otsu、Invert threshold、Mask threshold を調整する。
  10. 変更後、少し待つと同じ mask レイヤーが自動更新される。
  11. mask がよければ Create Skeleton を押し、骨格レイヤーと手動分類用 order labels レイヤーを作る。

重要なのは、長方形を描いただけでは切り抜きレイヤーは作られない点です。切り抜きは必ず Add ROI を押した後に実行されます。

全体像

実装は、大きく 2 つに分かれています。

ファイル 役割
src/leaf_vein_workflow/_widget.py napari の画面、レイヤー、ボタン、通知を扱う
src/leaf_vein_workflow/crop.py 画像配列をどこで切るかを計算する
src/leaf_vein_workflow/threshold.py 画像配列を grayscale 化し、閾値で二値 mask を作る
src/leaf_vein_workflow/skeleton.py 二値 mask から骨格画像を作る

初心者向けに言うと、_widget.py は「画面の係」、crop.py と threshold.py は「計算の係」です。

napari への登録

napari は src/leaf_vein_workflow/napari.yaml を読んで、このパッケージの widget を見つけます。

このファイルでは、leaf_vein_workflow._widget:CropWidget が widget として登録されています。つまり napari のメニューからプラグインを開くと、CropWidget クラスが作られます。

CropWidget の初期化

CropWidget は、プラグインの本体です。

作られた直後に、主に次の準備をします。

  • napari viewer を self.viewer に保存する。
  • ROI レイヤーと元画像レイヤーの対応表を作る。
  • ROI レイヤーと crop レイヤーの対応表を作る。
  • crop レイヤーと mask レイヤーの対応表を作る。
  • Add ROI ボタンとステータス表示を作る。
  • Use Otsu、Invert threshold、閾値入力を作る。
  • Add ROI ボタンが押されたら add_roi() が動くようにする。
  • Use Otsu が押されたら use_otsu_threshold() が動くようにする。
  • 閾値や Invert threshold が変わったら、少し待って mask が自動更新されるようにする。
  • 新しいレイヤーが追加されたら _on_layer_inserted() が動くようにする。
  • すでに開かれている画像があれば、それにも ROI レイヤーを準備する。

ここでのポイントは、プラグイン起動後に画像を開いた場合だけでなく、すでに画像が開いている状態でプラグインを起動した場合にも対応していることです。

画像が追加されたとき

画像レイヤーが追加されると、_on_layer_inserted() から _prepare_image_layer() が呼ばれます。

_prepare_image_layer() は、次の確認をします。

  1. 追加されたレイヤーが napari の Image レイヤーか。
  2. その画像が、プラグイン自身が作った crop レイヤーではないか。
  3. すでに ROI レイヤーと結びついている画像ではないか。

この確認を通った画像だけに、ROI 用の Shapes レイヤーを作ります。

ROI レイヤーには、metadata として次の情報が入ります。

metadata 意味
leaf_vein_workflow_role = roi_shapes この Shapes レイヤーは ROI 用である
source_image = 元画像名 どの画像から作られた ROI か

さらに、内部の辞書 _roi_to_image によって、ROI レイヤーと元画像レイヤーの対応を保存します。

ROI が編集されたとき

ユーザーが ROI を描いたり編集したりすると、_on_roi_data_changed() が呼ばれます。

ここで確認しているのは、主に次の 2 点です。

  • ROI が 1 つだけあるか。
  • その ROI が長方形か。

ROI が 0 個、または 2 個以上ある場合は、ステータス表示で「長方形を 1 つだけ描いてください」と案内します。長方形以外の場合は、警告を出します。

ただし、この段階ではまだ画像を切り抜きません。ここでは「準備ができたか」を確認しているだけです。

Add ROI を押したとき

Add ROI ボタンを押すと、add_roi() が動きます。

add_roi() は、まず次の順番でチェックします。

  1. 現在選択されているレイヤーが ROI 用 Shapes レイヤーか。
  2. その ROI レイヤーが元画像と結びついているか。
  3. ROI が 1 つだけか。
  4. ROI が長方形か。
  5. ROI が画像と重なっているか。

すべて通った場合だけ、実際の切り抜き処理に進みます。

切り抜き処理では、rectangle_to_slices() と crop_to_rectangle() の 2 つを使います。

rectangle_to_slices()

rectangle_to_slices() は、ROI の頂点座標を NumPy の slice に変換する関数です。

たとえば、長方形 ROI の座標がだいたい次の範囲だったとします。

座標 値
y の最小値 1.2
y の最大値 3.7
x の最小値 2.1
x の最大値 4.9

この場合、関数は次のように整数の範囲へ変換します。

軸 変換後
y slice(1, 4)
x slice(2, 5)

最小値側は floor で下に丸め、最大値側は ceil で上に丸めます。これにより、ROI に含まれる画素を取りこぼしにくくしています。

また、ROI が画像の外にはみ出している場合は、画像の範囲内に切り詰めます。完全に画像と重ならない場合は、エラーにします。

対応している画像は、現在の MVP では次の 2 種類です。

  • 2D grayscale image
  • 2D RGB/RGBA image

crop_to_rectangle()

crop_to_rectangle() は、実際に画像配列を切り抜く関数です。

内部では、まず rectangle_to_slices() を呼び出して、切り抜く y 範囲と x 範囲を決めます。その後、画像が 2D なら次のように切ります。

image_array[y_slice, x_slice]

RGB/RGBA のように最後の軸が色チャンネルの場合は、色チャンネルを残すために次のように切ります。

image_array[y_slice, x_slice, :]

戻り値は .copy() された配列です。これは、元画像の一部を参照するのではなく、切り抜き画像として独立したデータにするためです。

crop レイヤーの作成と更新

add_roi() は、切り抜いた画像を napari の Image レイヤーとして追加します。

新規作成時には、次の情報を指定します。

  • レイヤー名は 元画像名 ROI
  • RGB/RGBA 画像なら rgb=True
  • translate に ROI の左上位置を入れる
  • metadata に crop レイヤーであることを記録する

translate を設定する理由は、切り抜き画像を元画像上の ROI 位置に重ねて表示しやすくするためです。

同じ ROI レイヤーからすでに crop レイヤーが作られている場合は、新しいレイヤーを増やさず、既存レイヤーの data と translate を更新します。

mask レイヤーの作成と更新

Add ROI 後、または閾値 UI を変更した後に、現在の crop Image レイヤーから二値 mask を作ります。

入力として使えるのは、本プラグインが Add ROI で作った crop レイヤーです。crop レイヤーそのものを選択していても、対応する ROI レイヤーを選択していても、その crop を使います。

二値化では、まず threshold.py の to_grayscale() で画像を 2D grayscale に変換します。RGB/RGBA 画像の場合は RGB だけを使い、alpha は無視します。その後、threshold_image() が閾値以上の画素を 1、その他を 0 とする mask を返します。

Invert threshold が有効な場合は、閾値以下の画素を 1 として扱います。これは、葉脈が背景より暗い画像で使う想定です。

Use Otsu ボタンは、現在の crop 画像から otsu_threshold() で閾値を推定し、閾値入力欄に入れます。閾値入力欄や Invert threshold が変わると、すぐには再計算せず、短い待ち時間の後にまとめて mask を更新します。

mask は napari の Labels レイヤーとして作られます。レイヤー名は crop レイヤー名 vein mask です。同じ crop レイヤーからすでに mask が作られている場合は、新しいレイヤーを増やさず、既存 mask レイヤーの data と translate を更新します。

skeleton レイヤーと order labels レイヤーの作成

Create Skeleton を押すと、現在の vein mask Labels レイヤーから骨格画像を作ります。

骨格化では、skeleton.py の skeletonize_mask() が mask の 0 より大きい画素を前景として扱い、scikit-image の skeletonize() で 1 pixel 幅の骨格にします。

結果は mask レイヤー名 skeleton という Labels レイヤーとして追加または更新されます。さらに、手動分類用に mask レイヤー名 order labels という空の Labels レイヤーも作ります。

order labels の値は、次の用途を想定しています。

label 意味
0 未分類または背景
1 primary
2 secondary
3 tertiary
4 higher order / minor

同じ shape の order labels レイヤーがすでにある場合は、ユーザーが手で塗った内容を上書きしません。mask の shape が変わった場合は、既存の手動分類を壊さないため、新しい order labels レイヤーを作ります。

エラーや警告になる例

次の場合は、切り抜き処理に進まず、警告またはエラーになります。

状況 理由
ROI レイヤー以外を選択している どの ROI を使うか分からない
ROI が 0 個 切り抜く範囲がない
ROI が 2 個以上 MVP では 1 個だけ対応
ROI が長方形ではない MVP では rectangle のみ対応
ROI が画像と重ならない 切り抜ける画素がない
画像が 2D grayscale または RGB/RGBA ではない MVP の対応範囲外
crop レイヤーがまだない状態で Use Otsu を押す 二値化する画像がない
crop 画像に NaN や inf が含まれる 閾値計算が信用できない

テストで確認していること

tests/test_crop.py では、napari に依存しない切り抜き計算を確認しています。

  • 小数座標が floor と ceil で正しく slice になること。
  • 画像外にはみ出た ROI が画像範囲に切り詰められること。
  • RGB 画像の色チャンネルが保たれること。
  • 空の ROI や画像外 ROI がエラーになること。
  • 未対応の画像 shape がエラーになること。

tests/test_threshold.py では、napari に依存しない二値化計算を確認しています。

  • grayscale 画像をそのまま float の 2D 配列として扱えること。
  • RGB/RGBA 画像を grayscale に変換できること。
  • 手動閾値で明るい前景と暗い前景の両方を mask にできること。
  • Otsu 閾値が単純な二峰性画像を分けられること。
  • 未対応の画像 shape がエラーになること。

tests/test_skeleton.py では、napari に依存しない骨格化計算を確認しています。

  • 2D mask から骨格画像を作れること。
  • Labels 形式の整数 mask でも、0 より大きい画素を前景として扱うこと。
  • 空 mask や 2D 以外の入力がエラーになること。

tests/test_widget_import.py では、Qt backend がある環境で widget を import できることと、画像追加から ROI レイヤー作成、Add ROI による crop レイヤー作成までを確認しています。 現在はさらに、crop レイヤーから mask Labels レイヤーが自動作成され、Otsu 閾値や手動閾値の変更で自動更新されることも確認しています。 また、mask から skeleton Labels レイヤーと手動分類用 order labels レイヤーが作られ、既存の order labels が上書きされないことも確認しています。

開発時に見る順番

挙動を追うときは、次の順番で読むと理解しやすいです。

  1. README.md でユーザー操作を確認する。
  2. src/leaf_vein_workflow/napari.yaml で widget 登録を確認する。
  3. src/leaf_vein_workflow/_widget.py の CropWidget.__init__() を見る。
  4. _prepare_image_layer() で画像追加時の動きを見る。
  5. _on_roi_data_changed() で ROI 編集時の確認を見る。
  6. add_roi() でボタン押下時の処理を見る。
  7. src/leaf_vein_workflow/crop.py で切り抜き計算を見る。
  8. use_otsu_threshold()、_schedule_mask_update()、_update_mask_from_controls() で二値化 UI の処理を見る。
  9. src/leaf_vein_workflow/threshold.py で grayscale 化と二値化計算を見る。
  10. create_skeleton() と src/leaf_vein_workflow/skeleton.py で骨格化と手動分類用レイヤー作成を見る。

まとめ

現在の実装は、葉脈解析そのものではなく、葉脈解析の前段階として「人が画像上で ROI を指定し、その範囲を切り出し、葉脈候補 mask をプレビューする」ための最小機能です。

設計上は、napari 依存の GUI 部分と、NumPy ベースの計算部分が分かれています。このため、今後 ROI 管理や保存機能を足す場合は _widget.py を中心に、切り抜き仕様を変える場合は crop.py を中心に、二値化仕様を変える場合は threshold.py を中心に変更すればよい構造になっています。
