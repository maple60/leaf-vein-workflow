葉脈形質の測定法と既存ツールの比較報告

エグゼクティブサマリ

葉脈密度指標としての VLA（vein length per leaf area）は、total VLA = すべての葉脈長 / 葉面積が基本であり、実務上とくに重要なのは major VLA = 1–3 次脈長 / 葉面積、minor VLA = 4 次脈以上の脈長 / 葉面積である。総 VLA は多くのツールで扱えるが、major/minor をそのまま分離して算出できる既存ツールは少ない。今回調べた範囲では、標準的かつ最も厳密なのは ImageJ/Fiji を用いる手動トレース系であり、major/minor VLA を「直接」得るには、手動の脈次分類、または階層ラベル付きセグメンテーション結果に対する追加計算がほぼ必須だった。phenoVein、LEAF GUI、LeafVeinCNN、eCognition 法、最近の DL 法は、総 VLA や脈幅、分岐点、アレオールなどの定量では有用だが、major/minor VLA をワンクリックで出す設計にはなっていないか、あるいは 主脈のみを対象にしている。1

実用上の結論は明確である。最低限 major VLA を確実に取りたいなら、(a) cleared leaf を作成し、(b) whole-leaf の低倍率像と intercostal 領域の高倍率像を併用し、(c) ImageJ/Fiji で major/minor を分けてトレースする方法が、現在でも最も再現性が高い。高スループットで total VLA や network traits を取りたいなら phenoVein または LeafVeinCNN が第一候補で、主脈中心のリアルタイム計測なら MobileNetV2-DeepLabV3+ 系が候補になる。ただし後者は論文自身が「主脈中心」と明記しており、minor VLA 取得には向かない。hierarchical major/minor を自動化したい場合は、HALVS 系の階層セグメンテーションが最も将来性があるが、現状は研究コード／データセットの性格が強く、VLA 指標の最終算出は自作後処理が必要である。23456

一方、ユーザー指定のツールのうち LeafJ は葉形計測用で葉脈密度には非対応、RhizoVision Explorer は root 向けで off-label では使えても葉面積規格化や major/minor VLA の標準機能はない、VeinViewer は医療用静脈可視化装置で植物葉脈解析ツールではない。したがって、これらは比較対象には含めるべきだが、葉脈 VLA 測定の中核候補ではない。78910

調査範囲と評価基準

本報告では、要求された必須項目として major VLA を最低限取得したいという条件を中心に、可能なら minor VLA も含めて評価した。major/minor の定義は、近年の生理生態系の文献で一般的な major = 1–3 次脈、minor = 3 次超または 4 次以上に揃えた。total VLA はその和として扱った。文献上も、major VLA と minor VLA を葉面積当たりの脈長として分け、total VLA を両者の和として定義する例が多い。11

比較軸は、依頼内容に従って次の通りに統一した。すなわち、前処理（クリアリング、染色、透過/反射、非破壊計測の可否）、画像取得法（スキャナ・顕微鏡・マクロ/カメラ・3D）、解像度要件、ソフトウェア名とバージョン、入力形式、処理ワークフロー、自動化レベル、出力指標、major/minor VLA の算出可否と方法、精度・検出限界、計算時間、必要ハードウェア、ライセンス/費用、長所・短所、利用例である。なお、ツールによっては最新版が継続配布されていても、論文で検証された版と異なることがあるため、可能な限り「論文版」と「現在配布版」を分けて記した。12

この主題では、「測れること」と「厳密に測れること」を区別する必要がある。総脈長や骨格長、分岐点数を返すツールは多いが、major/minor VLA は脈次の判別が前提であり、単に二値化・骨格化するだけでは直接は得られない。そのため、報告中では各ツールについて 直接算出可、間接的に可、不可 を明示した。13

major VLA と minor VLA を厳密に測るための標準設計

葉脈 trait の標準的な実験設計は、cleared leaf を作成して葉脈を可視化し、whole-leaf で major vein を、代表的な lamina サブサンプルで minor vein を測るという二段構えである。PROMETHEUS の標準プロトコルでも、葉脈密度、各脈次の脈径、自由終端脈数などを取得する前提として clearing と imaging を行うことが示されている。さらに Sack らは、葉全体を高倍率で一様に解像することは多くの種で非現実的であり、major vein は whole-leaf cleared scan から、minor vein は lamina の高倍率サンプルから測るのが現実的だと述べている。1415

前処理では、研究室プロトコルとして 5% NaOH による長時間クリアリング、漂白、サフラニン O 染色、グリセロール封入後のスキャンが広く使われる。Cavender-Bares Lab の手順では、NaOH 処理後に漂白し、0.05% Safranin O in ethanol で染色、グリセロールでマウントしてスキャンしている。別の自動法では、5% NaOH で 7 日間透明化し、toluidine blue で染色して 40× 顕微鏡撮影を行っている。つまり、major/minor を厳密にとる研究では clearing + 染色 + 透過系撮影が依然として主流である。非破壊・反射撮影・3D 法も出てきたが、現時点では総 VLA に強く、major/minor の厳密分離ではまだ補助的である。161718

解像度要件にも注意が必要である。phenoVein では 脈長と VLA は約 400 dpi 以上で安定し、脈幅推定は 3000 dpi 以上、かつ対象脈幅が少なくとも 5 pixels は必要と報告されている。LEAF GUI をめぐる検証では、低品質・低倍率・ダウンサンプリング画像が大きな誤差源であり、十分に脈が判別できる画質が必要とされた。ImageJ 手動法の実務プロトコルでも、minor vein 判読のために画面上で少なくとも 600× まで拡大して確認するよう指示されている。つまり、major/minor を分けるほど細い脈次まで扱うなら、dpi の数字だけでなく、最細脈が何 pixel で表現されるかが本質的な基準になる。1920

flowchart LR
    A[試料採取] --> B[クリアリング]
    B --> C[染色または無染色透明化]
    C --> D{撮像法の選択}
    D -->|whole leaf| E[スキャナまたはマクロ撮影]
    D -->|minor veins| F[顕微鏡高倍率撮影]
    E --> G[major veins 可視化]
    F --> H[minor veins 可視化]
    G --> I[前処理と二値化]
    H --> I
    I --> J[骨格化 / 手動トレース / DNNセグメンテーション]
    J --> K{脈次分類できるか}
    K -->|はい| L[major/minor を分離]
    K -->|いいえ| M[total VLAのみ算出]
    L --> N[major VLA = Lmajor / A]
    L --> O[minor VLA = Lminor / A]
    M --> P[total VLA = Ltotal / A]

このフローの重要点は、major/minor VLA の分離は「脈次分類」工程に依存することである。phenoVein や LEAF GUI のように総脈長や edge 情報を返すツールでも、脈次を自動分類しない限り出力されるのは total VLA であり、major/minor は手動または追加アルゴリズムが必要になる。逆に、HALVS のような階層ラベル付き手法は major/minor への道筋を提供するが、面積正規化と最終集計は別途実装する必要がある。2122

主要ツールの個別分析

ImageJ と Fiji はなぜ依然として基準法なのか

ImageJ の手動トレース法は、自動化レベルこそ低いが、major/minor VLA を厳密に分けたいという今回の要件には最も適合する。理由は単純で、ユーザーが 1 本ずつ tracing するため、脈次の判定を人間が直接反映できるからである。Sack らは LEAF GUI と比較する際の基準法として ImageJ 1.44o による digital tracing を採用しており、標準法として扱っている。研究室実務プロトコルでも、代表領域を crop し、midrib を避け、必要なら 600× 以上まで拡大しながら tracing し、最終的に長さ合計を面積で割って VLA を計算する。41

この方法の長所は、major/minor を直接返せること、画像品質の問題を人間判断で吸収できること、論文間の比較可能性が高いことである。短所は、時間がかかること、作業者差が出うること、高スループットに向かないことである。したがって、major VLA を最低限確実に取るという要件なら最有力だが、何百〜何千枚の処理には向きにくい。Fiji の AnalyzeSkeleton は、この手動または外部セグメンテーション後の skeleton から branch 数・平均長などを追加抽出する補助として有用であるが、脈次分類そのものはしない。42

LEAF GUI は総 VLA とネットワーク記述には強いが major/minor 直出しではない

LEAF GUI は MATLAB で作られた stand-alone の academic free ソフトで、thresholding・cleaning・segmentation により cleared leaf の vein network と areole を抽出し、総 network length、vein density、network area、edge length/width、areole statistics を返す。whole-leaf statistics の例では、計算時間はサーバで 58–84 秒、より遅いラップトップでは 190–264 秒程度と報告されている。43

ただし major/minor VLA については、LEAF GUI 自体が脈次分離を標準機能として持つわけではない。後年の論文でも LEAF GUI で venation information を抽出した後、別法に基づいて vein levels を分けるという使い方が見られる。さらに Sack らの検証では、低品質・低倍率画像や downsampling、さらに LEAF GUI のアルゴリズム上の artifact により VLA の見かけ上の増加や 5%以上の誤差が生じうると指摘された。よって LEAF GUI は、cleared whole-leaf の total VLA・areole 記述には有用だが、major/minor の厳密測定には単独では不十分という評価になる。44

phenoVein は total VLA 用の実用解として最もバランスがよい

phenoVein は顕微鏡画像・マクロ画像の両方を扱える葉脈専用ツールで、leaf/background 分離、vesselness filtering、二値化・骨格化、目視確認と任意修正、脈長評価、脈幅推定という明快なパイプラインを持つ。jpg、png、8/16-bit tif、bmp を読め、明視野・暗視野いずれ由来の画像にも対応する。manual correction がしやすい点が強みである。45

出力は、total skeleton length、projected leaf area、vein density、piecewise vein length/width、branching point 密度、ending point 密度、areole 数・面積など非常に充実している。一方で、論文本文が明示する通り、automated classification of vein orders は実装されていない。したがって major/minor VLA は、出力 skeleton や手動指定した vein pieces を利用して追加分類・再集計すれば可能だが、標準ボタンでは出ない。46

性能面では、length measurement は手動 segmentation と R² = 0.9996、leaf 1 枚あたり 1–2 分、葉サイズ・画質によっては 1–4 分で、角度依存も VLA で 0.8% 未満と小さい。解像度は VLA なら約 400 dpi 以上、width は 3000 dpi 以上が必要で、width 推定には少なくとも 5 pixels 幅が望ましい。したがって、major/minor の自動分離を要しない total VLA 計測では、phenoVein が現在でも非常に強い選択肢である。ソフトは phenoVein 1.0 が Windows 版 MeVisLab 上で動き、BSD-3 で公開されている。4748

LeafVeinCNN と最近の機械学習系は高スループットに強いが major/minor は追加実装が前提

Xu らの LeafVeinCNN 系は、葉脈画像に対して CNN で segmentation を行い、その後 graph extraction と multiscale network statistics へ進む枠組みである。現在の配布版は v2.14.00 で、学習済みモデルは 1.68 µm resolution の画像に基づき、MATLAB app 版では MATLAB 2020b 以降と Deep Learning / Image Processing / Parallel Computing toolbox を要求する。Windows standalone 版も配布されている。研究対象としては、総脈ネットワークや階層ループ分解、multiscale traits の抽出に強い。4950

ただし、この系統のツールも major/minor VLA を直接返すわけではない。graph は得られるため、太さや位置、階層推定を追加すれば order 別 VLA に進めるが、標準配布物の中心は total/network-level traits である。したがって、既に高解像度 cleared image があり、大量サンプルの total VLA や network topology を高速に取りたい研究には向くが、今回のように major VLA を必須とする設計では、そのままでは不十分である。51

最近の DL 手法の中では、MobileNetV2-DeepLabV3+ 法とHALVS 系階層セグメンテーションを分けて考えるべきである。前者は MIoU 81.50%、mPA 92.89%、9.81 fps、長さ 96.3642%、幅 96.1358% と高速だが、論文自身が “main veins” を主対象としており、minor VLA 取得には使えない。後者は 1°–3° の階層ラベルを持つ 5,057 枚の高解像度 dataset を提供し、major/minor を自動化する唯一の本格的方向性を示すが、最終的な VLA 集計は利用者の後処理に依存する。TTH-Net は segmentation 精度向上には有用でも、order 別 VLA には直接つながらない。525354

eCognition 法は batch total VLA に特化した商用ルート

Zhu らの object-oriented classification 法は、顕微鏡画像を remote sensing 的に扱い、eCognition Developer 64 で multiscale segmentation とルールベース分類を行う。試料は 5% NaOH 透明化、toluidine blue 染色、40× 顕微鏡撮影で、9 樹種で 平均精度 96.40%以上、計算速度は従来の ImageJ 手動法より 87.3%以上向上した。55

ただしこの方法が返すのは本質的に total leaf vein density であり、major/minor の order 分離は想定していない。またソフトは商用である。したがって、大量の顕微鏡画像から total VLA を一括処理する用途には適するが、major/minor VLA を必須とするプロジェクトには不向きである。56

非破壊計測と、今回の主題に不適なツール

2025 年の multispectral + 3D 法は、digital fringe projection を用いて 1936 × 1464 pixels, 120 Hz のカメラと 720 × 1280 projector により、非平坦葉から leaf area、vein length、VLA を直接測る。従来の flatten 2D 法との差は 3% 未満で、非破壊 total VLA としては有望である。しかし major/minor 分離は未実装で、主脈を hand-trace して比較した補助検証はあるものの、主要出力は total VLA である。したがって field-like 条件の non-destructive total VLA には魅力があるが、major/minor VLA 用にはまだ早い。57

LeafJ は葉身と葉柄の境界、葉面積、周囲長、円形度などの葉形ツールであり、葉脈密度には対応しない。RhizoVision Explorer は高コントラスト branching structure の長さ・径・分枝を測る root 向けソフトで、開発者が leaf vein analysis デモを示してはいるが、公式説明は root image analysis であり、葉面積規格化と脈次分離を含む major/minor VLA の標準機能はない。VeinViewer は医療用静脈可視化装置であり、植物葉脈 trait 計測の比較対象としては基本的に除外すべきである。5859606162

選定指針と結論

今回の比較から、major VLA を最低限確実に取得するという要件に対して、現時点で最も妥当な実装は次の順序になる。まず、cleared leaf を作り、whole-leaf 低倍率像で major veins、高倍率サブサンプル像で minor veins を可視化する。次に、ImageJ/Fiji で order を意識して手動トレースし、major/minor を別々に長さ集計して葉面積で割る。これが最も厳密で、文献上の互換性も高い。高スループットが必要なら、phenoVein または LeafVeinCNN で total VLA と骨格を取り、major/minor は追加の手動分類または自作スクリプトで分けるのが現実的である。636465

より具体的には、厳密性を最優先するなら ImageJ/Fiji 手動、total VLA と幅・アレオールを含む実務的自動化なら phenoVein、大規模バッチと network science 的特徴量なら LeafVeinCNN、major vein の高速抽出なら MobileNetV2-DeepLabV3+、将来的に major/minor を自動化したい研究開発なら HALVS がそれぞれ最適に近い。LEAF GUI は歴史的に重要で現在も利用例はあるが、major/minor VLA が研究目的の中核であるなら第一選択ではない。6667686970

総括すると、既存ツール群のボトルネックは「細脈の検出」ではなく「脈次の信頼できる分類」にある。total VLA の自動化はかなり進んでいるが、major/minor VLA の自動算出は依然として限定的である。したがって、今回の要件に最も適した運用は、標準化された clearing・撮像・手動/半手動 order 分離を核にし、必要に応じて phenoVein や LeafVeinCNN を補助的に組み合わせるハイブリッド設計である。71727374
